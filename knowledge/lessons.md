# Lessons — read at the start of every session; append what you learn the hard way.

A lesson is anything learned the hard way that's worth a durable rule — a correction, a gotcha, or a
non-obvious finding (not only "you did X, do Y instead"). `/wrap` proposes candidates and asks
before adding any.

Format (one line per lesson, newest at the bottom):
`[date] | what happened / what was learned | rule or takeaway next time`

[2026-06-06] | hardcoded "X installed" version facts drifted — ".NET 9" surfaced wrong twice (stated for ADR-0003; baked into the wiki-init template) when the box was on 10.0.108 | verify versions at runtime (`dotnet --version`); never assert an installed version in docs/templates
[2026-06-06] | a repo reorg broke path references inside all 7 immutable ADRs | treat path/location refs in Accepted ADRs as mechanically migratable on a reorg — immutability protects the decision, not file paths
[2026-06-06] | `grep -v` on a token also hid a file whose NAME contained it (wiki-init.md was skipped when excluding "wiki-init") | when renaming, match the path column or re-grep per-file — don't filter the whole output line
[2026-06-06] | spec 0002 (read path) silently depended on 0001 storing each chunk's Text, but 0001's tests only asserted vector/dimension/determinism — a vector-only store would pass 0001 and break 0002's citations | at a cross-spec seam, pin the produced data shape as a contract on the PRODUCING side and assert it there; don't just describe the dependency in the consumer
[2026-06-06] | a behavior fixed in a spec's Constraints prose (populated-store "not found", citations still shown) had no matching check in How-to-verify, so it could ship untested | every behavior stated in Constraints needs a named check in How-to-verify — especially the demo's trust beats (e.g. anti-hallucination)
[2026-06-07] | `dotnet new sln` on .NET 10 emits a `.slnx` (XML solution), not `.sln` — `dotnet sln add … LandDoc.sln` failed | on .NET 10 expect `.slnx`; reference it explicitly in `dotnet sln`/`build`/`test`
[2026-06-07] | `UglyToad.PdfPig` publishes only prerelease-tagged builds (1.7.0-custom-5); `dotnet add package` failed "no stable versions available" | add PdfPig with `--prerelease` (or pin the prerelease version)
[2026-06-07] | a deterministic embedder hashed with `string.GetHashCode()` would break across runs — it's per-process randomized; used FNV-1a instead | for any determinism-dependent hashing use a fixed algorithm (FNV-1a), never `string.GetHashCode()`
[2026-06-07] | minimal-API multipart file endpoints reject the upload with 400 (antiforgery) unless `.DisableAntiforgery()` is set — a test fails on 400, not the real status | add `.DisableAntiforgery()` to minimal-API form-upload endpoints (and in a skeleton return 501 unconditionally so red-tests fail for the right reason)
[2026-06-07] | `claude-code-action` workflow templates ship read-only (`pull-requests: read`), so the reviewer ran green but posted nothing and `@claude` could read but not reply/push (`permission_denials`, "No buffered inline comments" in the run log) | grant each job the writes it needs — reviewer: `pull-requests: write` + the plugin's `--comment` flag; `@claude` author: `contents`+`issues`+`pull-requests: write` — the default is read-only and fails silently
[2026-06-07] | `issues:[opened,assigned]` + a gate keyed on `issue.author_association` re-fires `@claude` on any reassignment of a trusted-author `@claude` issue (no fresh intent; with write perms could push) | mention-triggered `@claude` listens to `issues:[opened]` only; gate assignment-based triggers on `assignee.login`, not `author_association`
[2026-06-07] | GitHub's native issue dependencies (blocked-by/blocking) can't be set via the GitHub MCP tools or `gh` CLI — UI/API only | record dependencies as issue-body text (`Blocked by: #N`) as the source of truth; treat native links as a manual UI step
[2026-06-07] | the `@claude` GitHub-action runner has no `dotnet restore` — it can't add NuGet packages, regenerate `packages.lock.json`, or run tests (it worked around the SDK requirement with raw HTTP) | do dependency/lock changes + verification locally (worktree → locked-restore/build/test → push the fix to the PR branch); let the bot do pure code edits; gate everything on CI
[2026-06-07] | RTL `getByLabelText(/question/i)` matched two elements — the input's `aria-label` AND a `<section aria-labelledby>` heading "Ask a question" (the region's accessible name) | scope ambiguous label queries to `getByRole('textbox', { name })`; a loose `getByLabelText` regex collides with any element carrying that accessible name
[2026-06-07] | the slice backend constructs `AnthropicChatClient` per request *before* handler validation, so with no `ModelClient:ApiKey` even blank-question / non-PDF calls return 500, not 400/409 | live FE-degradation status codes aren't observable without the key — cover degradation with a mocked client; note that eager per-request adapter construction defeats validation-first error codes
[2026-06-07] | a curly apostrophe in UI copy ("isn’t available") broke a `/not available/` assertion ("isn’t" ≠ "not") | phrase assertable UI strings plainly (or match loosely) — curly punctuation silently fails substring/regex test assertions
[2026-06-07] | `@claude` on a new *issue* opens a new branch/PR, but `@claude` on a *PR comment* amends that PR's branch — routing a review-finding fix through a fresh issue forces merge-first | to fix a finding on an open PR, comment `@claude` on the PR (or fix it locally on the branch), never file a new issue
[2026-06-08] | the `/adr` flow propagates a decision to living `docs/` but not `specs/` — spec 0002 kept the old posture and even asserted "ADR-0007 not superseded", which ADR-0012 made false | after an ADR that changes a cross-cutting seam, reconcile `specs/` too, not just `docs/`; grep specs for the superseded ADR refs
[2026-06-08] | `dotnet add package` in a multi-project lock-file solution only regenerates the edited project's `packages.lock.json`; a referencing test project's lock then fails `restore --locked-mode` with NU1004 | after add/remove, run `dotnet restore --force-evaluate` across the solution to resync ALL lock files, then verify with `--locked-mode`
[2026-06-08] | docs-only changes don't need the code branch→PR flow — `main` isn't branch-protected and the convention gates code (`backend/`/`frontend/`) | for docs-only edits push to `main` directly (`git push origin HEAD:main`); reserve PRs for code
[2026-06-08] | claude-code-review rejected `@claude`'s PR fix-push with "Workflow initiated by non-human actor: claude (type: Bot)" — the action's `allowed_bots` defaults empty (no bots) | set `allowed_bots: 'claude'` (or `'*'`) on the reviewer workflow; `pull_request` reads the workflow from the merge-ref vs current `main`, so it reaches open PRs on their next push
[2026-06-08] | claude-code-action doesn't auto-open PRs — by design it pushes a branch + a "create PR" link, and default-`GITHUB_TOKEN` PRs don't trigger downstream CI | to make the bot submit PRs, allow-list `gh pr` in `claude_args` + set `GH_TOKEN` in the step env (App/PAT token if you also want CI to fire)
[2026-06-08] | a `window` drop listener registered in a `useEffect([onFiles])` closes over a stale `busy` value — adding `if (busy) return` inside the handler reads the value captured at registration time, not the current render value | for boolean guards inside window/document event listeners with a fixed dep array, sync to a ref (`const busyRef = useRef(busy); busyRef.current = busy`) and read `busyRef.current` inside the handler; the ref update is a side-effect but it's fine as an inline assignment on every render
[2026-06-08] | the non-interactive (harness) shell defaulted `dotnet` to an 8.0-preview at `/usr/local/share/dotnet`, so `dotnet build` failed `NETSDK1045` targeting `net10.0` — while the interactive shell resolved 10.0.108 (the Homebrew `/opt/homebrew/bin/dotnet`) | on `NETSDK1045` / SDK-version surprises run `which -a dotnet` and pin the right binary; a tool/harness shell's PATH order can differ from the interactive login shell's
[2026-06-08] | a prompt-injection test crafted a filename with a literal `\n`, but HttpClient's `MultipartFormDataContent.Add` rejects a newline in the `Content-Disposition` filename (`FormatException`) — the test crashed in setup, never reaching the server | you can't transmit a newline through the typed multipart filename param; unit-test newline/CR sanitization directly, reserve the HTTP path for transmittable injection chars (e.g. brackets)
[2026-06-08] | xUnit `Assert.Throws<T>` requires an EXACT exception type and rejects subclasses — `JsonDocument.Parse` throws `JsonReaderException` (: `JsonException`), so `Assert.Throws<JsonException>` failed | use `Assert.ThrowsAny<T>` when the code can throw a derived exception type
[2026-06-08] | a `/wrap` or "commit to main" repeatedly risked landing on the wrong branch (an `@claude` issue/feature branch) or a detached mid-rebase HEAD (`(no branch, rebasing main)`) | before any commit/wrap, check `git branch --show-current` and for an in-progress rebase; commit to the intended branch only
[2026-06-08] | `dotnet run` ignored `ASPNETCORE_URLS`/env-var overrides because launchSettings.json's profile wins — the app listened on the profile port, not the one I set | pass `--no-launch-profile` (or edit launchSettings) when driving Kestrel via env vars
[2026-06-08] | a Container App revision that boots with `KeyVault:Uri` set but whose managed identity lacks the KV role (or before RBAC propagates) fails at config load — and `az containerapp up` starts the app immediately | deploy without the vault URI first → assign identity + grant `Key Vault Secrets User` → add `KeyVault__Uri` in a follow-up `update` (rolls a revision once access exists)
[2026-06-08] | a CI identity with only `AcrPush` can't run `az acr build` — the quick-build schedules a server-side run that push-only rights don't cover | grant `Contributor` scoped to the ACR for `az acr build` (or build in-runner with buildx + `AcrPush`)
[2026-06-08] | `git merge-base --is-ancestor` reported every merged `@claude` branch as NOT merged — squash-merge replays branch content as a new commit, so branch tips are never ancestors of main | don't prune by ancestry in a squash-merge repo; verify via PR merged-state (`gh pr list --head <branch> --state all`) or an empty content diff before deleting
[2026-06-08] | commits pushed to a feature branch AFTER its PR was squash-merged never reached main (the PR was already closed) — the follow-up work sat orphaned on the merged branch | when a PR merges before follow-up lands, get those commits to main deliberately: cherry-pick (docs-only → push to main) or open a fresh PR; never assume a later push to a merged branch deploys/lands

## Single-user auth — Easy Auth gate + app-level allowlist (spec 0013 / ADR-0022)
**TL;DR:** Brought auth into scope by ADR, spec'd it, shipped the app-level allowlist middleware (PR #52), configured Easy Auth + Entra on the live Container App, and gated the public URL to the owner — anonymous access now 401/302s.
Tags: #auth #easy-auth #entra #aca #spec-0013 · Notes touched: [[easy-auth-on-container-apps]]
Evidence: [[knowledge/docs/specs/0013-single-user-auth-easy-auth-gate-app-allowlist]] · [[knowledge/docs/decisions/0022-single-user-entra-auth-easy-auth-gate-app-level-allowlist]] · PR #52 / `feat/spec-0013-auth-allowlist-middleware` · issues #49–#51

### Decisions
- **Decision:** ADR-0022 — single-user auth moves **in** scope (RBAC/multi-user stays out): Container Apps Easy Auth (Entra ID) as the platform gate **plus** an app-level allowlist on the injected principal header — defense in depth so a platform misconfig can't silently expose the app.
- **Decision:** auth is the sixth config-selected seam — `Auth:Mode` = `none` (default; local/offline/tests unchanged) | `easyauth` (live); allowlist in `Auth:AllowedPrincipalIds` (object IDs, non-secret).
- **Decision:** the Easy Auth client secret lives as an **ACA secret** (`microsoft-provider-authentication-secret`), not Key Vault — it's consumed by the platform sidecar, not app config.
- **Decision:** owner identity = `hector@HectorReyes.dev` (object id `96b6d850-…`), confirmed against the signed-in Azure account before allowlisting.

### Findings / remember
- **Finding:** ACA `authConfigs/current` rejects PATCH (Method Not Allowed) and the CLI doesn't expose `allowedPrincipals` — set the platform allowlist by GET → merge `validation.defaultAuthorizationPolicy.allowedPrincipals.identities` → PUT.
- **Finding:** Easy Auth's `RedirectToLoginPage` only 302s browser-shaped requests (`Accept: text/html`); plain `curl` gets **401** — that 401 *is* the pass result for an anonymous smoke check, not a failure to chase.
- **Finding:** the middleware never parses the `X-MS-CLIENT-PRINCIPAL` claims blob — Easy Auth owns authentication; the app only checks *which* principal arrived (ADR-0022 trust boundary).

### Changes
- ADR-0022 authored + accepted; scope posture propagated to CLAUDE.md, README, PRD, ARCHITECTURE (new cross-cutting AuthN/AuthZ bullet), knowledge index (`d96e1f7`).
- Spec 0013 authored + accepted, committed spec-first (`1fcc41d`); issues #49–#51 created (dependency chain, label `spec-0013`).
- Backend (`#49` → PR #52, squash-merged): `Auth/AuthOptions.cs`, `Auth/EasyAuthAllowlistMiddleware.cs`, `Program.cs` binding + startup fail-fast (unknown mode / empty allowlist), 7 tests in `AuthMiddlewareTests.cs` — suite 125/125 green.

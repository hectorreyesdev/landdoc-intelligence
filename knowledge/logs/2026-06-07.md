## Claude GitHub automation — reviewer comments, @claude pickup, /issues command
**TL;DR:** Made the auto-reviewer actually post inline comments, gave `@claude` write-capable pickup behind a trusted-author gate, and added an `/issues` command that turns a spec into a dependency-ordered set of GitHub issues — wiring the spec→issue→PR→review loop.
Tags: #ci #github-actions #workflow #process #commands · Notes touched: [[ci-pr-review]] · [[workflow-harness]]
Evidence: PR #5 (`ed776ba`) · PR #6 (`9f72ca8`) · PR #7 (`e918450`) · branch claude/project-docs-structure-Uct2o

### Decisions
- **Decision:** Reverse the earlier "no GitHub issues" stance — **adopt issues as the tracker for spec-derived work** via the new `/issues` command (spec→issue→PR→review loop). Process decision, log-recorded (so was the original); not an app ADR.
- **Decision:** The CI reviewer posts inline via the code-review plugin's **`--comment`** flag + **`pull-requests: write`**, and is deliberately **never** given `contents: write` — it comments, never pushes (separation of duties).
- **Decision:** `@claude` is **mention-triggered (not assignee)**, gated to trusted `author_association` (OWNER/MEMBER/COLLABORATOR), with **full-pickup writes** (`contents` + `issues` + `pull-requests`) so it can deliver, not just talk.
- **Decision:** `/issues` records dependencies as **issue-body text** (`Blocked by: #N`) — the durable source of truth — since the GitHub tools/`gh` can't set GitHub's native blocked-by links (UI/API only); native links are an optional visibility step.

### Findings / remember
- **Finding:** the `claude-code-action` templates ship **read-only** — both the reviewer and `@claude` ran green but posted nothing until permissions were widened (the reviewer logged `permission_denials` + "No buffered inline comments").
- **Finding:** the auto-reviewer's **first real comment** caught a genuine bug in my own PR #6 — `issues:[opened,assigned]` + an `author_association` gate re-fires Claude on any reassignment of a trusted-author `@claude` issue; fixed to `issues:[opened]`.
- **Finding:** GitHub **native issue dependencies** (blocked-by/blocking) are GA (Aug 2025) but not settable via the GitHub MCP tools or `gh` CLI — UI/API only.
- **Finding:** rebasing the dev branch onto `main` after each squash-merge cleanly drops already-upstream commits ("patch contents already upstream"), so one branch served PRs #6/#7 without redundant commits.

### Changes
- `.github/workflows/claude-code-review.yml` (PR #5): add `--comment`; grant `pull-requests: write`.
- `.github/workflows/claude.yml` (PR #6): full-pickup write perms + `author_association` trust gate; dropped the `issues.assigned` trigger (reviewer-flagged re-trigger risk).
- `.claude/commands/issues.md` (new, PR #7): the `/issues` workflow command; `.claude/commands/spec.md`: offers `/issues` on spec acceptance (new step 5; Report → 6).
- Notes updated: [[ci-pr-review]] (permissions + issues-now-adopted), [[workflow-harness]] (`/issues` = 5th command).

**TL;DR:** Authorized the spec-0002 read path (QaPassage port amendment + ADR-0010 slice-default Anthropic + a real CI gate), handed it to `@claude` via issue #9, fixed both review findings, and merged PR #10 — first full spec→issue→@claude→PR→review→merge loop.

### Decisions
- **Decision:** amend Accepted spec 0002 (not flag-only) to authorize the **`QaPassage` port DTO** — `IChatClient.AnswerAsync` takes `QaPassage`, not storage `Chunk` — because `IChatClient`'s own doc-comment requires a spec to change the interface. Applies hexagonal ports (ADR-0002/0004); no new ADR.
- **Decision:** ADR-0010 — **Anthropic-direct is the slice-default chat adapter** (official `Anthropic` .NET SDK), `ModelClient:ChatProvider` defaults to `anthropic`. Slice-scoped; does **not** supersede ADR-0007 (Foundry stays production-primary) — references it, doesn't edit it.
- **Decision:** add a deterministic **CI gate** (`.github/workflows/ci.yml`: `dotnet build`+`test` on `pull_request`, `--locked-mode` restore) BEFORE filing the issue, so the bot's PR is actually compiled/tested — the review bot + human eyes never compile the code.

### Findings / remember
- **Finding:** the `@claude` GH-action runner has **no `dotnet restore`** — it can't add NuGet packages, regenerate `packages.lock.json`, or run tests. It used raw HTTP to dodge the SDK; finding #2 (official SDK + lock) had to be done locally.

- **Finding:** `--locked-mode` restore + the committed lock make the **lock diff an automatic provenance gate** — a package add that doesn't commit the regenerated lock fails CI.

## Frontend vertical slice — spec 0003 (UI) + ADR-0011 (single-origin) + scaffold/tests/CI
**TL;DR:** Specced the thin React/TS UI as an *acceptance target* (0003), recorded the single-origin SPA↔API topology that designs CORS out of existence (ADR-0011), then scaffolded `/frontend` (Vite + RTL, 23 tests green) behind a paths-filtered CI gate — PR #13.
Tags: #frontend #react #typescript #vite #vitest #0003 #adr #ci #single-origin #tdd · Notes touched: [[frontend-architecture]] · [[agent-proxy-gaming]]
Evidence: [[knowledge/docs/specs/0003-frontend-vertical-slice]] · [[knowledge/docs/decisions/0011-single-origin-spa-api-topology]] · PR #13 (`frontend/0003-vertical-slice`) · commits 07247c3 (spec) · 153883d (ADR) · 8d84578 (spec reconcile) · b7cc6a6 (scaffold) · c7bf48f (CI)

### Decisions
- **Decision:** Spec 0003 pins the UI as an **acceptance target**, not a build plan — the four states, the two endpoints' shapes, 400/409/501 degradation, the "typed client is the only `fetch`" rule, and acceptance — precisely to stop an agent gaming the UI ([[agent-proxy-gaming]]).
- **Decision:** ADR-0011 — **single-origin in every environment, so CORS never exists**: dev = Vite proxy → `:5084`; prod = Azure Static Web Apps linked backend (named, not built). The typed client uses relative paths only; backend compute host left unpinned. Builds on ADR-0006 (framework); supersedes nothing.
- **Decision:** Test bar = **Vitest + React Testing Library** component tests + manual E2E; dev wiring = **Vite proxy** (no backend change). Frontend tooling (Vite/Vitest) lives under ADR-0006's umbrella — not a new ADR.
- **Decision:** Frontend CI is a **separate** `frontend-ci.yml` (not a 2nd job in `ci.yml`) because `paths:` filters are workflow-level; `npm ci` enforces the lockfile (supply-chain gate), Node 22, offline (no secrets).
- **Decision:** Reconciled spec 0003's "currently 501" framing → `/ask` **now live** (0002 merged); kept the 501 path as **defensive** degradation, not the present state (amendment noted under Status).

### Findings / remember
- **Finding:** `getByLabelText(/question/i)` matched **two** elements — the input's `aria-label` AND the `<section aria-labelledby>` heading "Ask a question"; a loose label regex collides with a region's accessible name. Scope to `getByRole('textbox', { name })`. (lesson)
- **Finding:** The slice backend **constructs `AnthropicChatClient` per request before handler validation**, so without `ModelClient:ApiKey` every `/documents` and `/ask` call 500s — even blank-question / non-PDF paths. Live 400/409 codes aren't observable without the key; FE degradation is covered by mocked-client tests instead. (lesson)
- **Finding:** Live proxy confirmation = real `application/problem+json` with the **worktree's own stack-trace paths** coming back through `:5173` — proof the Vite proxy reaches the live backend (vs. Vite's HTML or a connection refusal).
- **Finding:** `npm install @latest` resolved current majors cleanly — React 19.2 · TS 6.0 · Vite 8.0 · Vitest 4.1 — green on Node 24 locally, Node 22 in CI.

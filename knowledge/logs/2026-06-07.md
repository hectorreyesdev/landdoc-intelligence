## CI PR reviewer (GitHub Actions) + workflow conventions
**TL;DR:** Stood up an automated Claude PR reviewer via GitHub Actions, reconciled it with the App's own generated workflows, and pinned the team conventions (branch/PR for code; no GitHub issues).
Tags: #ci #github-actions #workflow #process · Notes touched: [[ci-pr-review]]
Evidence: PR #1 (`1213181`) · PR #2 (app, `a47c793`) · PR #3 (`af56d9b`) · commits d491fd7 · d3327df · branch main

### Decisions
- **Decision:** Automated PR review runs via **`anthropics/claude-code-action@v1`** using the official **code-review plugin** (`/code-review:code-review`) — not a hand-rolled prompt.
- **Decision:** Auth is the **Claude Max OAuth token** (`CLAUDE_CODE_OAUTH_TOKEN` via `claude setup-token`), not an API key. Secret is set on the repo (the App's install flow added it).
- **Decision:** Final workflow set = the App's two (`claude.yml` = @claude assistant, `claude-code-review.yml` = auto reviewer); removed my duplicate `claude-review.yml` (PR #3).
- **Decision:** Adopted the **branch/PR convention for code from now on** (feature branch → PR → squash-merge; never commit code to `main`). First applied via PRs #1/#3.
- **Decision:** **No GitHub issues** — the tracker stays specs + PRs + `/wrap` logs; revisit a board only if non-spec chore/bug flow grows (then hybrid: issues for non-spec work only).

### Findings / remember
- **Finding:** A newly-added `claude-code-action` workflow shows a **green check but SKIPS** (workflow-validation guard requires the file to match the default branch) — it does **not** review its own introducing PR. First real run is the next PR after merge; a green check can mean "skipped" → verify the run log / PR comments.
- **Finding:** `/install-github-app` generated its **own two workflows** (via PR #2), which duplicated my hand-rolled one — running both = double review per PR.
- **Finding:** Squash-merge makes `git branch -d` report "not fully merged" (the branch tip isn't in `main`'s history); use `-D` to delete a squash-merged branch.

### Changes
- Added then refined the reviewer workflow (PR #1: `d491fd7` add, `d3327df` switch to OAuth + plugin), merged; App added `claude.yml` + `claude-code-review.yml` (PR #2); removed duplicate `claude-review.yml` (PR #3, `af56d9b`).
- Pruned all stale merged branches (local + remote); repo back to just `main`, in sync.

## Backend slice — 0001 document-ingestion write path (skeleton → green → reconcile)
**TL;DR:** Scaffolded `/backend` (.NET 10 modular monolith) with a first red test, drove spec 0001's ingest pipeline (parse → extract → chunk → embed → store) to green via TDD, then reconciled the design docs to the code.
Tags: #backend #dotnet #0001 #tdd #rag · Notes touched: [[backend-testing]]
Evidence: [[knowledge/docs/specs/0001-document-ingestion-write-path]] · [[knowledge/docs/decisions/0002-split-model-access-into-chat-and-embedding-clients]] · [[knowledge/docs/decisions/0005-in-memory-vector-store-slice-azure-ai-search-production]] · [[knowledge/docs/decisions/0008-deterministic-hashing-embeddings-for-slice]] · commits eb83def (skeleton) · 7cb77f0 (0001 + doc reconcile) · branch feat/backend-skeleton

### Decisions
- **Decision:** `IChatClient` is **Shape A** — a high-level port (`ExtractFieldsAsync → IReadOnlyList<ExtractedField>`, `AnswerAsync → string`), mandated by spec 0001/0002's "fake `IChatClient` returning canned fields"; the real prompt/parse will live in the chat adapter, so the Extraction module stays a thin port call.
- **Decision:** Modules are folders/namespaces in ONE `LandDoc.Api` project (Storage · Model · Ingestion · Extraction · Qa); `Retrieval` reserved until 0002.
- **Decision:** Chunking is config-driven (`Chunking:MaxChars`/`Overlap`, default 120/30) — a general parameter tuned small so the tiny synthetic fixture yields >1 chunk, not keyed to the fixture.
- **Decision:** Doc reconcile went `code`-canonical for every flagged item except `ScoredChunk` (skipped); the user committed code + reconciled docs together in 7cb77f0.

### Findings / remember
- **Finding:** The 0001 happy path is green through *real behavior* — fields from `IChatClient` (faked in tests), chunks from the general chunker, vectors from the hashing embedder; `grep src/` confirms **no fixture values in production code** (canned values live only in `FakeChatClient`).
- **Finding:** Tests inspect the store through the public `IVectorStore.TopK` seam (probe vector + huge k ⇒ all chunks) — no port widening for test-only access. Each store-touching test news its own factory for isolation.
- **Finding:** Several `.NET 10` build gotchas hit this session (`.slnx`, PdfPig prerelease, stable-hash determinism, minimal-API `DisableAntiforgery`) — see lessons.

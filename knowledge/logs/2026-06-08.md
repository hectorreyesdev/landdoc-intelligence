**TL;DR:** Packaged the app as one image (SPA + API, one origin, port 8080), wired Key Vault as an opt-in config source via managed identity, deployed live to Azure Container Apps, and armed passwordless OIDC CI/CD that auto-deploys on merge to `main`. ### Decisions
- **Decision:** Single image serves SPA + API on one origin (port 8080, no CORS) on **Azure Container Apps** — realizes ADR-0011's single-origin principle, replacing its "Static Web Apps linked backend" placeholder. ADR-0016 authored & Accepted; **supersedes ADR-0011** (prod realization only — single-origin/relative-paths contract carries forward; 0011 Status flipped, body frozen).
- **Decision:** Secrets come from **Key Vault via `DefaultAzureCredential`**, added as an opt-in config source gated on `KeyVault:Uri` — same code resolves to `az login` locally and the Container App's **system-assigned managed identity** in Azure; vault secret names (`AzureOpenAI--*`, `Anthropic--*`) map `--`→`:` onto existing config keys, so **no adapter change**. App's MI granted `Key Vault Secrets User` (vault is RBAC-mode).
- **Decision:** CI/CD = GitHub Actions on push to `main` → `az acr build` → `az containerapp update`, authenticated by **passwordless OIDC** (Entra app `gh-landdoc-deploy` + federated credential for `…:ref:refs/heads/main`); runtime secrets never touch CI (the app's MI reads them). Workflow arms only once `deploy.yml` lands on `main`.
- **Decision:** Held the commit/PR until docs were reconciled (per the human); reconcile direction = **code/new-reality canonical** for the SWA→container drift.

### Findings / remember
- **Finding:** `POST /ask` returning **409 empty-store** (vs a no-credential 500) is the cheap positive signal that the vault key was pulled and the embedding call succeeded — one embedding call, no corpus needed.
- **Finding:** Deploy the app **before** granting the KV role — `az containerapp up` starts it immediately, and a revision that boots with `KeyVault:Uri` set but no role (or pre-RBAC-propagation) fails at config load. Add the identity + role, then set `KeyVault__Uri` in a follow-up `update` (rolls a fresh revision with access).
- **Finding:** `az acr build` needs **Contributor** on the registry (it schedules a server-side run) — `AcrPush` (push-only) is insufficient.
- **Finding:** `dotnet run` ignores `ASPNETCORE_URLS`/env overrides because launchSettings.json's profile wins — use `--no-launch-profile` to honor env vars.

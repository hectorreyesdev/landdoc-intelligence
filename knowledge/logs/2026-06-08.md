## Best-effort field extraction (spec 0001 amendment)
**TL;DR:** Decoupled field extraction from the ingest write path — a failing `IChatClient` provider no longer 500s ingest; the doc is still chunked/embedded/stored and returns `201` with empty `fields`.
Tags: #backend #tdd #ingestion · Notes touched: —
Evidence: [[knowledge/docs/specs/0001-document-ingestion-write-path]] (amended) · PR #15

### Decisions
- **Decision:** Extraction is **best-effort** — provider failure yields empty `fields` + stored chunks, not a 500. Authorized as a one-line spec 0001 amendment *before* the patch (avoids unrecorded spec drift).

### Changes
- `DocumentIngestionService.IngestAsync` — wrapped `fieldExtractor.ExtractAsync` in a try/catch that excludes `OperationCanceledException` (cancellation still propagates); injected `ILogger` so the swallowed failure is observable.
- New `IngestionExtractionResilienceTests` — throwing chat client → asserts `201` + empty fields + N>1 chunks landed in the store.
- spec 0001 amendment (Constraints + matching How-to-verify check); `API.md` error-model reconciled (provider-failure-at-ingest is not a 500).

### Findings / remember
- **Finding:** Extraction ran *before* chunk/embed/store, so a throw both 500'd ingest **and** stored nothing — the catch had to sit so the store path still runs.

## Azure OpenAI GPT as the live chat provider (ADR-0012)
**TL;DR:** Recorded ADR-0012 (Azure OpenAI GPT live, supersedes 0007+0010) and implemented it — `AzureOpenAIChatClient` + per-provider config; Anthropic-direct demoted to config-swap fallback; Foundry stub deleted.
Tags: #adr #azure-openai #anthropic #config #reconcile · Notes touched: —
Evidence: [[knowledge/docs/decisions/0012-azure-openai-gpt-live-chat-adapter-per-provider-config]] · [[knowledge/docs/specs/0002-rag-qa-with-citations]] (amended) · [[knowledge/docs/AZURE-CONFIG]] · issue #16 · PR #15, #17

### Decisions
- **Decision:** ADR-0012 — live slice chat = **Azure OpenAI GPT** (`gpt-5.4-mini`, Chat Completions); the PAYG sub can't reach Claude-in-Foundry (needs Enterprise/MCA-E; PAYG gets 0 TPM/RPM for Marketplace models), but directly-sold Azure OpenAI is PAYG-eligible.
- **Decision:** Adopt a **per-provider config schema** (`AzureOpenAI:*`, `Anthropic:*`) so both adapters resolve at once and the swap is config-only; `ChatProvider` default flips to `azureopenai`.
- **Decision:** ADR-0012 **supersedes ADR-0007 and ADR-0010** (whole-file) — a "What carries forward" section preserves 0007's gateway/port-swappability thesis and 0010's Anthropic-direct (demoted to fallback). 0007/0010 Status lines flipped; bodies frozen.

### Changes
- New: `AzureOpenAIChatClient : IChatClient` (Azure.AI.OpenAI 2.1.0, client built once in ctor, clear config guards) · `AzureOpenAIOptions` · `AnthropicOptions` · `AzureOpenAIChatClientTests` (ctor/options validation, no live call).
- `ModelClientOptions` trimmed to selectors; `AnthropicChatClient` reads `AnthropicOptions`; Program.cs switch → `azureopenai` default + `anthropic` fallback; `FoundryChatClient` deleted; `appsettings.json` non-secret defaults only.
- Docs: new `AZURE-CONFIG.md` handoff (live stack, KV secret *names* only); ADR-0012; reconciled API.md, STACK, ARCHITECTURE, GLOSSARY, DATA-FLOW, PRD, spec 0001, spec 0002 to the decision; post-merge reconcile dropped the "impl pending" markers + pinned SDK versions.

- **Finding:** No secret *values* in the repo — KV secret **names** only in AZURE-CONFIG; hosting reads via managed identity, dev via `dotnet user-secrets`.
